# デモ3: コードとインフラを横断してレビューする

## 3-1. 横断レビュー

```text
`src/`、`infra/`、`docs/system-context.md`、`docs/architecture.md` をまとめてセキュリティレビューしてください。
変更は行わず、単独の問題一覧ではなく、複数の弱点をつないだ攻撃経路を考えてください。

重要な攻撃経路を「入口 → コード上の弱点 → インフラ上の弱点 → 到達先・影響 → 根拠ファイル」の順に簡潔に示してください。
確認できない部分は「追加確認が必要」としてください。
```

## 3-2. 指摘を1件だけ修正

```text
先ほどの指摘から、アプリケーションコード側で修正できる問題を1件だけ選び、必要最小限の変更で修正してください。
関係のないリファクタリングは行わず、再発防止用のテストを1つ追加して実行してください。

最後に「変更したファイル / 修正内容 / テスト結果」だけ簡潔に報告してください。
```
